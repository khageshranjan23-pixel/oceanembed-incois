# Start here: the complete numbered OceanEmbed implementation

**Use this order. Do not start with a multi-year download or the final website.** First make the software work with synthetic data; then make one real-data sample correct; then scale, train, validate, and publish.

This is a research implementation, not a pretrained accurate ocean product. Software tests cannot guarantee scientific accuracy. Real provider metadata, QC and independent evaluation remain essential. The included website makes unsupported/unavailable results visible rather than inventing them.

## Step 1 — Choose where each part will run

Use your laptop for VS Code, the smoke test, data inspection and website development. Use a Linux GPU workstation/server for real model training if your laptop lacks a suitable NVIDIA GPU. Start with one 16–24 GB GPU as a practical development target; memory use depends on batch, history and network width. Profile before buying capacity. For processing, 32 GB RAM is a useful starting point, 64 GB provides headroom. Estimate disk from actual regional sample downloads; original global products can be far larger than processed cubes.

Do not rent a web GPU. The public website serves previously computed results on CPU.

**Result:** you know which machine is for training and which serves the website.

## Step 2 — Download and extract the code

1. Download `OceanEmbed-NIO-Code.zip` from the response.
2. Windows: right-click the ZIP → **Extract All**. macOS: double-click the ZIP. Linux: use your archive manager.
3. Put the extracted `oceanembed-kit` folder somewhere easy, such as `Documents/Projects/oceanembed-kit`.
4. Keep the entire folder structure. Do not copy only one Python script to another directory.

Files you should see: `README.md`, `pyproject.toml`, `run_smoke.py`, `oceanembed/`, `web/`, `configs/`, `docs/`, `tests/`.

**Result:** a complete local project folder, not a ZIP being viewed inside an archive manager.

## Step 3 — Install Python 3.12 and VS Code

1. Visit https://www.python.org/downloads/ and install Python 3.12 for your OS.
2. On the Windows installer, enable **Add python.exe to PATH** when offered.
3. Install VS Code from https://code.visualstudio.com/ .
4. Open VS Code → **File → Open Folder** → select `oceanembed-kit`.

**Result:** the VS Code terminal is in the project directory containing `pyproject.toml`.

## Step 6 — Run the installation test

```bash

```

This verifies numerical invariants and code behaviour. It does not prove model accuracy on the real ocean.

**Result:** the tests finish successfully in your environment.

## Step 14 — Download bathymetry

Use an official bathymetry product such as GEBCO and obtain a regional rectilinear subset with the same halo. Save the provider citation/version.

Inspect whether the file contains elevation positive upwards or depth positive downwards. The kit expects **positive-down ocean depth; land excluded**. If the source is elevation, a sign conversion is necessary.

This is a geometric mask, not a temperature predictor. Average bathymetry is an approximation near mixed coastal cells; the scientific contract describes the stricter wet-area treatment for coastal production work.

**Result:** a reviewed bathymetry file and an unambiguous sign convention.

## Step 18 — Fill the ingestion configuration

1. Open `configs/ingest-template.json`.
2. Choose **File → Save As** and save `configs/ingest.json`.
3. Replace each `REPLACE_...` field from the inspected metadata.
4. Configure all seven surface variables, teacher and bathymetry.
5. Use `multi_file:true` for compatible file globs; otherwise use a single NetCDF path.
6. Rename actual source coordinates to `time`, `latitude`, `longitude`, and `depth` where applicable.
7. Set unit conversion explicitly.
8. Set source-specific QC rules only from that product's manual.
9. Set `reviewed:true` for every entry after review.
10. Save.

Illustrative SST entry, only if your file matches these names/units:

```json
{
  "reviewed": true,
  "files": "data/raw/sst/*.nc",
  "multi_file": true,
  "variable": "analysed_sst",
  "expected_units": "kelvin",
  "rename": {"lat": "latitude", "lon": "longitude"},
  "scale": 1,
  "offset": -273.15,
  "min_samples_per_day": 1,
  "min_support": 0.8,
  "qc": []
}
```

If the source is already Celsius, offset must be 0. The exact unit string must match inspection. Empty QC is only acceptable when you have reviewed the product's existing valid mask and determined no further flag rule is needed. Bit-field QC needs proper decoding, not a guessed numerical threshold.

For CCMP complete daily means, use four valid samples per day. For GLORYS, keep the depth dimension. For a surface-only extra singleton depth, use `select_index:{"depth":0}` only when appropriate.

**Result:** an explicit, reviewable mapping from actual source files to the model's physical channels.

## Step 19 — Harmonize the pilot

Expected folders include `data/harmonized/sst`, `sss`, `sla`, `current_u`, `current_v`, `wind_u`, `wind_v`, `teacher`, plus `bathymetry.nc`.

**Result:** one file per source per day on the common grid.

## Step 22 — Pack the training cube

```bash
python -m oceanembed.pack --input data/harmonized --output data/cube --start 2016-01-01 --end 2025-12-31
```

Expected files include `x.npy`, `y.npy`, `support.npy`, `age.npy`, `wet.npy`, `dates.npy`, `lat.npy`, `lon.npy`, and `metadata.json`.

Inputs are seven channels. Targets are 15 levels. Test-period teacher targets remain missing. The loader creates seven-day windows on demand rather than storing repeated copies.

The initial age channel describes same represented-day inputs, not verified publication latency. This is retrospective reconstruction; NRT requires the additional availability workflow in the extensions.

**Result:** an efficient memory-mappable scientific cube.

## Step 23 — QC and thermodynamically convert Argo

```bash
python -m oceanembed.argo --directory data/raw/argo --out data/argo/profiles.csv
```

The primary path selects delayed-mode adjusted temperature/salinity/pressure with QC and error filters, converts pressure to depth, converts in-situ temperature to potential temperature, and interpolates only where supported. There is no fabricated 0 m observation.

Open `profiles.csv` and its audit JSON. Count profiles by split and depth. The error/gap thresholds are provisional engineering settings; assess sensitivity with training observations before freezing them.

**Result:** reproducible observation labels with explicit train/selection/calibration/test assignments.

## Step 24 — Fit normalization, seasonal climatology and EOF modes

```bash
python -m oceanembed.fit --cube data/cube --out runs/core --modes 8
```

Expected files: `runs/core/stats.npz` and `fit_manifest.json`.

Only training years are used. Temperature predictions will be climatology plus an anomaly, not a network relearning the entire seasonal mean. EOFs summarize vertical structure; missing below-bottom values are not filled with zero to fit PCA.

**Result:** statistics fitted without seeing test labels.

## Step 25 — Train a statistical baseline

```bash
python -m oceanembed.baseline --cube data/cube --stats runs/core/stats.npz --out outputs/ridge-selection --start 2022-01-01 --end 2022-12-31 --alpha 10
python -m oceanembed.evaluate --predictions outputs/ridge-selection --argo data/argo/profiles.csv --split selection --out outputs/ridge-selection-metrics
```

Inspect depth-wise RMSE, bias, anomaly correlation and skill. Compare a small predeclared regularization set on selection data if desired. Climatology is the essential reference. The stronger XGBoost/MLP/U-Net suite is described separately; do not claim superiority over unrun baselines.

**Result:** a benchmark your neural model must justify improving.

## Step 26 — Train the core model

On a CUDA GPU:

```bash
python -m oceanembed.train --cube data/cube --run runs/core --epochs 30 --width 16 --history 7 --batch 2 --patch 64 --device cuda
```

On CPU replace `cuda` with `cpu`, recognizing full-data training can be slow.

Inspect `runs/core/history.json`. The command saves `best.pt` and its model/config metadata. If memory is exhausted, reduce batch size first. Use the same model configuration when loading checkpoints.

The default model uses a CNN, temporal attention, EOF coefficient decoding and a residual. Width/epochs are starting settings, not guaranteed optimal values. Its provisional loss is masked Huber plus vertical and column-anomaly terms.

**Result:** a trained teacher-stage model, not yet a validated final accuracy claim.

## Step 27 — Test optional SSL and spatial context

For SSL create a new run folder and copy statistics:

```bash
python -c "import pathlib,shutil; pathlib.Path('runs/ssl').mkdir(parents=True,exist_ok=True); shutil.copyfile('runs/core/stats.npz','runs/ssl/stats.npz')"
python -m oceanembed.train --cube data/cube --run runs/ssl --ssl --epochs 15 --width 16 --history 7 --batch 2 --patch 64 --device cuda
python -m oceanembed.train --cube data/cube --run runs/ssl --pretrained runs/ssl/ssl.pt --epochs 30 --width 16 --history 7 --batch 2 --patch 64 --device cuda
```

Compare on matched selection observations. Optional `--spatial` adds bottleneck attention, but patch-only training does not establish basin-wide context. Full-domain fine-tuning uses `--patch 0 --batch 1` with a matching architecture. Advanced adapters/GradNorm remain behind controlled validation gates.

**Result:** measured decisions about extra complexity, not a larger architecture merely for presentation.

## Step 28 — Train the Argo observer

```bash
python -m oceanembed.observer --cube data/cube --run runs/core --argo data/argo/profiles.csv --epochs 100 --device cuda
```

This keeps the backbone frozen and learns observational residual correction plus a scale from training Argo. It selects the adapter using the permitted 2022 selection subset. Calibration and future-test observations are not used here.

Expected files: `observer.pt` and `observer.json`.

**Result:** a candidate correction that must be compared against the base model.

## Step 29 — Compare base and corrected selection performance

```bash
python -m oceanembed.predict --cube data/cube --runs runs/core --base-only --out outputs/base-selection --start 2022-01-01 --end 2022-12-31 --device cuda
python -m oceanembed.predict --cube data/cube --runs runs/core --out outputs/core-selection --start 2022-01-01 --end 2022-12-31 --device cuda
python -m oceanembed.evaluate --predictions outputs/base-selection --argo data/argo/profiles.csv --split selection --out outputs/base-selection-metrics
python -m oceanembed.evaluate --predictions outputs/core-selection --argo data/argo/profiles.csv --split selection --out outputs/core-selection-metrics
python -m oceanembed.compare --a outputs/core-selection-metrics/pairs.csv --b outputs/base-selection-metrics/pairs.csv --out outputs/observer-comparison.json
```

Negative corrected-minus-base RMSE favours correction. Inspect all depths and basin/season subsets. Keep the correction only if the benefit is meaningful and reproducible. Do not open the future test to make this decision.

**Result:** an evidence-based final model choice.

## Step 30 — Calibrate uncertainty on the reserved subset

The commands below assume the observer-corrected model was selected. If the base model wins Step 29, calibrate `outputs/base-selection` instead and add `--base-only` to final prediction in Step 31. Never mix a corrected-model calibration with base-only predictions.

For the selected corrected one-model configuration:

```bash
python -m oceanembed.evaluate --predictions outputs/core-selection --argo data/argo/profiles.csv --split calibration --out outputs/calibration
```

If using a three-member ensemble, first train the separate seeds/observers and export predictions with all members, then calibrate that ensemble—not one member. Use exactly the same member list for calibration and final prediction.

The calibration output is `outputs/calibration/calibration.json`. Too few valid observations/floats must cause a stop or a predesigned pooled calibration approach. Do not lower a threshold to obtain a desired result.

**Result:** pointwise intervals with a target coverage to be measured on future data, not a universal cellwise guarantee.

## Step 31 — Freeze and evaluate the future test

Freeze source versions, QC, splits, statistics, model/observer weights, calibration and evaluation rules. Preserve the code commit and run settings.

```bash
python -m oceanembed.predict --cube data/cube --runs runs/core --out outputs/final-test --start 2023-01-01 --end 2025-12-31 --device cuda
python -m oceanembed.evaluate --predictions outputs/final-test --argo data/argo/profiles.csv --split test --unlock-test --calibration outputs/calibration/calibration.json --out outputs/final-test-metrics
```

## Step 32 — Run the INCOIS comparison

Only after resolving the temperature convention, run the corresponding command:

```bash
python -m oceanembed.incois --predictions outputs/final-test --reference data/raw/incois.nc --out outputs/incois --temperature-kind potential --definition-source "Actual provider document/version/section confirming the convention"
```

If the documented variable is in-situ temperature, use `--temperature-kind in_situ` instead. Salinity is then used in the evaluator for thermodynamic conversion; it is not supplied to model inference.

The code aggregates predictions to the monthly reference grid. This comparison and raw Argo can share underlying observations; do not call them two completely independent observing systems.

**Result:** real PS-aligned benchmark files, or a clearly documented pending definition/access issue.

## Step 33 — Assemble a checked website bundle

Choose an empty output folder and a manageable date window for the public map. The prediction source should still contain every date used by the supplied evaluation so pair checks can run.
